# FIT5120-TE38-SignLanguage

FIT5120 TE38 team's formal capstone project — an Inclusive Auslan Learning Assistant
(see `Inclusive_Auslan_Learning_Assistant_Proposal.pptx`).

## `website/` — HandMirror (main app)

**Live:** https://handmirror.vercel.app (client, on Vercel) — talks to
https://handmirror-server-production.up.railway.app (API, on Railway), backed
by a shared MySQL database also hosted on Railway.

A full-stack Auslan sign-language reference, catalogued like a field
specimen collection: search or browse signs by keyword, synonym, or
category; open a sign to see its demonstration and usage notes; mark signs
as learned (tracked client-side in `localStorage`, no account required).

Covers Epic 1 (US1.1–1.4: search, tag browsing, sign detail, pagination) and
Epic 2 (US2.1–2.4: demonstration, playback controls, text description, mark
as learned) of the project's user stories.

**Stack:** React + TypeScript + Vite (`website/client`), Express + MySQL
(`website/server`, via `mysql2`).

**Structure:**
- `website/client` — the frontend (pages, components, API client, hooks)
- `website/server` — the Express API and database access layer
- `website/docs` — internal reading guides for the search/browse and
  detail/demonstration code paths (onboarding reference for the team)

**Run locally:**
```
cd website
npm run install:all
npm run seed         # populate the database — see server/.env.example for DB_* vars
npm run dev           # runs client (:5173) and server (:4000) together
```

**Deploy:**
- Client → Vercel. Framework preset auto-detects Vite; set the
  `VITE_API_BASE_URL` environment variable to the deployed API's `/api`
  base (e.g. `https://handmirror-server-production.up.railway.app/api`).
- Server → Railway (`npm start`). Needs `DB_HOST`, `DB_PORT`, `DB_USER`,
  `DB_PASSWORD`, `DB_NAME`, `CORS_ORIGIN` (the deployed client's origin), and
  `VIDEO_BASE_URL` — see `website/server/.env.example`.

## `web/` — prototype app

A client-only React + TypeScript + Vite web app implementing Iteration 1 + the
core of Iteration 2 from the proposal: a sign library/search, guided step-by-step
learning, a basic quiz, and webcam-based sign recognition practice.

```
cd web
npm install
npm run dev      # http://localhost:5173
npm run build    # type-check + production build
```

### Where this came from

The recognition pipeline (`src/lib/handModel.ts`, `signModel.ts`, `dtw.ts`,
`signRecorder.ts`) is a TypeScript port of
[gabguerin/Sign-Language-Recognition--MediaPipe-DTW](https://github.com/gabguerin/Sign-Language-Recognition--MediaPipe-DTW),
a Python/OpenCV desktop app that recognises isolated signs by extracting
MediaPipe hand landmarks, turning them into a rotation/scale-invariant
angle-based feature vector, and comparing a recorded attempt to reference
signs with Dynamic Time Warping (DTW).

Ported to the web, per the proposal's own "How the system works" slide and its
privacy risk mitigation ("process frames in-browser, store no video, require
no account"):

- **Landmark extraction** runs fully in-browser via `@mediapipe/tasks-vision`
  (WASM), not a Python/OpenCV backend — no video frame ever leaves the device.
- **Recording start/stop** uses automatic rest-pose segmentation (recording
  begins when a hand appears, ends after a run of hand-absent frames) instead
  of the original desktop app's manual "press r / press q" keys.
- **DTW** is a small hand-written TS implementation instead of `fastdtw`, since
  our sequences are short enough that the exact algorithm is fast enough in a
  browser tab.
- Only hand landmarks are used (not full Holistic/pose) — the recognition math
  never consumed pose landmarks anyway.

### Placeholder data — read before using this for anything real

`public/data/signs/*.json` (generated by `scripts/generate-placeholder-signs.mjs`)
contains **synthetic, procedurally generated hand motions**, not real Auslan
signs — they're labelled "Demo Sign A/B/C/D" rather than any real word. This is
deliberate: the proposal itself flags "online self-learning could teach
incorrect signs" as a named risk, and every real sign shown to a learner needs
to be checked by an Auslan-fluent signer first. The app displays a persistent
banner reminding of this.

To replace the dataset with real content: use the `/record` dev page (webcam
capture → same in-browser MediaPipe pipeline → download a landmark-only JSON
template, no raw video produced), verify the recording with an Auslan-fluent
signer, then drop the resulting file into `public/data/signs/` and add an
entry to `manifest.json`.

### Not yet built (out of scope for this prototype)

Iteration 3 (family mode, real-life conversation practice) and full
personalised-learning recommendations are not implemented — `Progress.tsx` is
a minimal localStorage-backed "attempts / accuracy per sign" view, not a
recommendation engine.
